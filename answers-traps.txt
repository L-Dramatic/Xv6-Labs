1. Which registers contain arguments to functions? For example, which register holds 13 in main's call to printf?

Answer:
According to the RISC-V calling convention, the first eight integer or pointer arguments to a function are passed in registers a0 through a7.

Based on the provided call.asm, in main's call to printf (`printf("%d %d\n", f(8)+1, 13);`), the compiler places the argument 13 into register a2. This is confirmed by the instruction at address 0x24: `li a2,13`. The other arguments, the format string address and the result of `f(8)+1` (optimized to 12), are placed in a0 and a1 respectively.


2. Where is the call to function f in the assembly code for main? Where is the call to g? (Hint: the compiler may inline functions.)

Answer:
There are no calls to function f or function g in the assembly code for main. The compiler has performed aggressive optimization.

Instead of generating call instructions (like `jal`), the compiler evaluated the entire expression `f(8)+1` at compile-time. It determined that `g(8)` returns `8+3=11`, so `f(8)` also returns `11`. Therefore, `f(8)+1` is `12`. The assembly code simply loads this final, pre-calculated value `12` into the argument register a1 with the instruction `li a1,12` at address 0x26. This is a combination of function inlining and constant folding.

4. What value is in the register ra just after the jalr to printf in main?

Answer:
The `jalr` (Jump and Link Register) instruction saves the address of the instruction immediately following it into the `ra` (Return Address) register.

In `call.asm`, the `jalr` instruction that calls printf is at address `0x34`. The instruction immediately following it is `li a0,0` at address `0x38`. Therefore, after the `jalr` executes, the `ra` register will hold the value `0x38`.


5. Run the following code.
	unsigned int i = 0x00646c72;
	printf("H%x Wo%s", 57616, &i);
What is the output? If the RISC-V were instead big-endian what would you set i to in order to yield the same output? Would you need to change 57616?

Answer:
- **Output:** `He110 World`
  - **Reasoning:** 
    - `57616` in decimal is `e110` in hexadecimal. So `%x` prints `e110`.
    - RISC-V is little-endian, so the integer `0x00646c72` is stored in memory with the least significant byte first: `72 6c 64 00`.
    - When `%s` treats the address of `i` as a string, it reads these bytes. According to the ASCII table, `0x72` is 'r', `0x6c` is 'l', `0x64` is 'd', and `0x00` is the null terminator. This forms the string "rld".
    - Combining the parts gives "He110 World".

- **Big-endian `i` value:** To produce the same memory layout (`72 6c 64 00`) on a big-endian machine, `i` would need to be set to `0x726c6400`.

- **Change `57616`?** No. The value `57616` is passed in a register, and its numerical value is independent of the machine's memory byte order (endianness).


6. In the following code, what is going to be printed after 'y='? Why does this happen?
	printf("x=%d y=%d", 3);

Answer:
- **What is printed:** An unpredictable, garbage value will be printed after 'y='.
- **Why this happens:** The `printf` function's format string `"%d %d"` tells it to expect two integer arguments after the string itself. These arguments are expected in registers `a1` and `a2` respectively. The code provides the value `3`, which is correctly placed in `a1`. However, no value is provided for the second `%d`, so `printf` reads whatever value happens to be in register `a2` from previous, unrelated operations. This value is uninitialized from the perspective of this `printf` call, hence it is garbage.
